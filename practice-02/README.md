## 4. Модель данных и функции

Задача — объект с полями `id`, `title`, `completed`, `priority`.

- `id` — положительное безопасное целое число, уникальное в пределах списка.
- `title` — строка, после `trim()` длиной от 1 до 100 символов.
- `completed` — логическое значение, при создании всегда `false`.
- `priority` — только `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

Файлы: `data.js` хранит исходные наборы и номер варианта, `task-service.js` содержит функции работы с задачами без вывода в консоль, `main.js` запускает сценарии и показывает результаты, `checks.js` сравнивает результаты функций с ожидаемыми.

Результаты операций: `createTask` при успехе возвращает `{ ok: true, task }`, при ошибке `{ ok: false, error }`. `findTaskById` возвращает найденную задачу или `undefined`. `getPendingTasks` и `getTaskTitles` возвращают новый массив. `getTaskStats` возвращает объект `{ total, completed, pending, progress }`. Операции `addTask`, `setTaskCompleted`, `renameTask` и `removeTask` при успехе возвращают `{ ok: true, tasks }` с новым массивом, при ошибке `{ ok: false, error }`.

**Почему id не равен индексу:** индекс — это текущее место задачи в массиве, и после удаления соседней записи он меняется. `id` — постоянный идентификатор записи, он не меняется, поэтому искать задачу нужно по `id` через `find`, а не через `tasks[id]`.  
**Почему getTaskStats возвращает число, а не строку с процентом:** число можно использовать в дальнейших расчётах и сравнениях, а строка получается после `toFixed()`, которое возвращает текст. Поэтому расчёт возвращает чистое число, а округление делается только при выводе в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив и новый объект изменяемой задачи (через spread). Остальные объекты в массиве не копируются, а используются повторно, их свойства при этом не меняются.

## 9. Вывод

В ПР1 расчёты шли над отдельными переменными, а здесь задача стала объектом, список задач — массивом, а все операции вынесены в функции модуля `task-service.js`. Функции ничего не выводят сами, а возвращают результат: объект задачи, новый массив или объект `{ ok, error }`. Решение о том, что показать в консоли, принимает `main.js`, поэтому ту же логику можно будет подключить к странице в ПР3.

Изменение данных сделано без мутации: добавление через spread массива, обновление через `map` и spread объекта, удаление через `filter`. Неизменность проверялась сравнением входных данных с исходными после каждой операции и на замороженных объектах (`Object.freeze`) в `checks.js`, а в `main.js` — выводом `demoTasks` и `variantTasks` после сценариев.

Ошибка, которую пришлось исправить, — пропущенный `return` в стрелочной функции с фигурными скобками (эксперимент 2): функция считала значение, но возвращала `undefined`.
